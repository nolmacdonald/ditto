# Using ditto as a template

This file exists only in the template. `scripts/rename_project.py` deletes both
it and itself once you have renamed your project.

## 1. Mark the repository as a template (one-time, ditto maintainer)

The **Use this template** button only appears once the repository is flagged as
a template on GitHub:

> Repository → **Settings** → **General** → check **Template repository**

Without this, users have to fork or `git clone`, which carries ditto's git
history into their project.

## 2. Generate and rename

```bash
# After clicking "Use this template" and cloning your new repository:
python scripts/rename_project.py my_package \
    --owner my-github-user \
    --repo my-repo \
    --description "One-line description of the project" \
    --author "Your Name"
```

Add `--dry-run` to preview. Add `--dist-name my-package` if the PyPI name should
differ from the import name (hyphens are legal on PyPI, not in an import).

Then:

```bash
uv lock          # regenerate the lockfile under the new project name
uv sync
uv run pytest
```

## 3. What is *not* automated

The script cannot make these decisions for you:

| Item | Where | Why manual |
|------|-------|------------|
| Logos and favicon | `docs/source/_static/logo/*.svg` | Replace the four SVGs with your own artwork. |
| Copyright holder | `LICENSE` | Set the year and legal name. |
| Copyright line | `docs/source/conf.py` | Set the year and name in `copyright`. |
| Example code | `src/<pkg>/example.py`, `tests/test_example.py` | Delete once you have real code; `docs/source/getting_started.rst` references it. |
| Dependencies | `pyproject.toml` | ditto ships numpy/scipy/pandas/matplotlib/pint. Trim to what you actually use. |
| GitHub Pages | Repo → Settings → Pages | Set the source to **GitHub Actions** so `docs.yml` can deploy. |
| Codecov | Repo → Codecov | Optional. CI is configured with `fail_ci_if_error: false`, so it is harmless if unconfigured. |
| Labels | `.github/labels.yml` | Apply them with the GitHub CLI or a label-sync action. |
| Branch protection | Repo → Settings → Rules | CI defines `lint`, `test`, and `build` as separate required checks. |

## 4. Every place the template name appears

For reference, or if you prefer to rename by hand. `ditto` appears in:

- `pyproject.toml` — `name`, `[project.urls]`, `[tool.uv.build-backend] module-name`,
  `[tool.pytest.ini_options] addopts` (`--cov=ditto`)
- `uv.lock` — package name (regenerated by `uv lock`)
- `src/ditto/` — the package directory itself
- `src/ditto/*.py` — module docstrings and intra-package imports
- `tests/*.py` — imports and docstrings
- `docs/source/conf.py` — `project`, `release`, `html_theme_options`, `html_context`
- `docs/source/index.rst`, `getting_started.rst`, `api/index.rst`
- `docs/source/api/generated/ditto*.rst` — autosummary stubs (regenerated by Sphinx)
- `docs/source/_templates/footer-logo.html`, `docs/source/_static/css/custom.css`
- `.github/ISSUE_TEMPLATE/*.yml`, `.github/workflows/ci.yml`
- `README.md`, `CONTRIBUTING.md`, `CHANGELOG.md`, `NEWS.md`, `LICENSE`

Verify nothing is left behind:

```bash
grep -rIn 'ditto\|nolmacdonald' --exclude-dir=.git --exclude-dir=.venv .
```
